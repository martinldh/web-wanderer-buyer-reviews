# Web Wanderer Buyer Reviews

使用 Apify 的 web_wanderer 抓取 TikTok Shop 商品详情页（商品卡）的公开买家评价，并输出好评、中评、差评与选品洞察。

## 适用场景

- 判断真实购买者哪些需求已经满足、哪些没有满足
- 发现质量、尺寸、容量、漏液、包装、配送、SKU 差异等问题
- 分析验证购买与激励评价比例
- 为选品周报提供商品需求与风险输入

## 不负责什么

本 Skill 只分析商品卡 / 商品详情页买家评价，不分析：

- 短视频评论区
- 直播间聊天
- 达人画像或视频归因
- 某条评价来自短视频、直播还是商品卡的来源归因

TikTok 可能把不同入口产生的订单评价汇总到商品页，但 web_wanderer 不返回下单来源字段，因此不能据此判断渠道。

## 输入格式

推荐输入 TikTok Shop 商品页 URL：

~~~text
https://shop.tiktok.com/mx/pdp/<商品ID>
~~~

也支持：

~~~text
https://www.tiktok.com/view/product/<商品ID>
<纯数字商品ID>
~~~

不支持视频 URL、直播间 URL、店铺 URL或分类页 URL。输入错误时，Skill 应停止并提示改用商品页 URL。

## 首次调用提示

首次使用时会先提示：

> 请提供 TikTok Shop 商品页 URL（例如 /mx/pdp/<商品ID>）或商品 ID。此 Skill 抓取的是商品卡买家评价，不是短视频评论或直播聊天；首次先做小样本与字段门禁，空结果不会被解释成“没有差评”。

## 推荐提示词模板

### 基础评价分析

~~~text
请使用 web-wanderer-buyer-reviews 分析这个 TikTok Shop 商品页的全部公开买家评价：

商品链接：<粘贴商品页 URL>
市场：MX

请输出：
1. 测试状态、实际返回条数和实际费用
2. 商品平台评分与星级分布
3. 好评、中评、差评数量、占比和主题
4. 已满足的购买需求
5. 尚未满足的需求与负面问题
6. SKU 差异
7. 验证购买、激励评价、空文本评价比例
8. 选品建议、主要风险和下一步验证动作

明确区分商品卡买家评价、短视频评论和直播聊天。
~~~

### 选品判断

~~~text
请用 web-wanderer-buyer-reviews 判断这个商品是否值得进入墨西哥 TikTok Shop 选品池。

商品链接：<粘贴商品页 URL>

重点判断：
- 用户真正愿意为哪些功能买单
- 差评是否集中在可修复问题
- 商品描述是否与实际体验不一致
- 哪些风险可能造成退货或售后
- 给出“立即自用 / 继续验证 / 暂不考虑”的结论

只使用商品卡买家评价作为购买体验证据；不要把短视频评论称为买家评价。
~~~

### 单个问题验证

~~~text
请使用 web-wanderer-buyer-reviews，专门检查这个商品的以下问题：

商品链接：<粘贴商品页 URL>
待验证问题：<例如：是否漏液、是否真的保温、是否适合小户型>

请统计：
- 相关评价数量
- 好评和差评比例
- 代表性问题主题
- SKU 或规格差异
- 证据强度与样本限制
~~~

## 输出口径

Skill 会按以下结构输出：

1. 测试状态：商品、市场、Actor、运行状态、费用、返回条数
2. 数据口径：商品卡买家评价；平台汇总评分 vs 实际返回行数
3. 好评 / 中评 / 差评：星级、数量、占比、主题
4. 质量信号：验证购买、激励评价、空文本、SKU、字段缺失、矛盾文本
5. 选品判断：已满足需求、未满足需求、风险和建议验证动作
6. 数据边界：未覆盖短视频评论、直播聊天和来源归因

星级分类规则：

- 4–5 星：好评
- 3 星：中评 / 混合评价
- 1–2 星：差评

如果返回 0 条评价，只能报告“Actor 未抓到评价”，不能报告“商品没有评价”或“没有差评”。

## 成本与安全

- 默认市场：MX
- 默认单次费用上限：0.50 美元
- 默认先测试单个商品
- 不保存 API Token、签名 URL、评价者身份、邮箱或其他个人信息
- 空结果、市场错配、商品 ID 不匹配时停止扩大抓取
